# Capability example coverage

The [capability collection](../demo/capabilities.html) is a consumer guide to current public behavior. It uses the same theme catalog, site shell and public package entry as the existing demos. A resource in a decoded catalog is not evidence that the corresponding widget is implemented. Raster output and runtime traces do not establish original-system fidelity.

[Diagnostics](../demo/diagnostic.html): geometry, slices and interactive playground. | Preview is chrome output, not a second managed window. ## Reproduce representative availability

- `capabilities.html?theme=1138`: themed tabs and whole-header surface; control traces and labeled column helper.
- `capabilities.html?theme=crayon-os`: whole-header surface rendered, missing right disclosure and latched bevel admission visible among other successful controls.
- `capabilities.html?theme=slimes`: missing whole-header face, procedural column fallback, CSS tab fallback, missing themed slider/bevel/disclosure output and procedural progress path.
- `capabilities.html?theme=windows-95`: a different successful resource set and compact artwork; useful at narrow widths.
- With 1138 selected, open **Try a different clipping context** and choose **Unknown**: actual `unsupported: unknown-clip`, not a simulated error.

These are implementation observations from the current collection, not permanent theme capability guarantees. Future engine changes can alter admission; the page reports fresh results on each request.

## Prioritized gaps

1. Public scheme menu and cursor APIs are absent; keep the visible limitation until real composition/interaction surfaces exist.
2. Full tab teardown remains a lifecycle follow-up; this example change fixes semantic ownership without extending scanner ownership.
3. Header admission remains bounded, and column interaction is separate application work. Expand diagnostics only for concrete consumer needs.
4. Prepared bitmap fonts/display profiles need independently justified caller data before a meaningful additional example can be provided.

After `npm run build`, run `npx playwright test --config tests/rendering-options/playwright.config.mjs tabs-accessibility.spec.mjs`. The regression starts and closes its own shared transports and tests the public entry separately from source (`/src/index.ts`) and the built bundle (`/dist/scriptoscope.js`); no preexisting preview server or base-URL override is needed. It uses a new HTML consumer fixture without historical captures or golden comparisons.
