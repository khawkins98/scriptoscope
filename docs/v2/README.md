# Integration contracts and decision records

The directory name records an architecture milestone, not the npm version.
Do not infer branch policy or completion from an old plan's title.

- **Integrate an application:** start with the [npm guide](../npm-consumer.md).
- **Upgrade an existing integration:** use the [migration notes](./integration-release-notes.md).
- **Look up owned theme contracts:** use [owned theme API](./owned-theme-api.md),
  [raster consumers](./raster-asset-consumers.md) and the public declarations.
- **Make an integration decision:** read [DECISIONS](./DECISIONS.md), including
  superseding amendments, before the original [PLAN](./PLAN.md) or
  [owned raster transport plan](./owned-raster-transport-plan.md).

Decision records and plans preserve the reasoning at their recorded revisions.
They are not a second release-status dashboard. Use [release notes](../../CHANGELOG.md)
and linked issues for released behavior and outstanding work. Runtime implementers
follow their [brief](../spec/engine/IMPLEMENTER-BRIEF.md) and assigned lane; these
links do not add allowed paths.
