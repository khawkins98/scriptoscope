# v2 decisions

Tracker: [#378](https://github.com/khawkins98/scriptoscope/issues/378). Plan: [PLAN.md](./PLAN.md) (architecture review, 2026-10-21).

**Naming note (2026-10-30).** "v2" in these decisions names two things: the decode-first engine generation under `src/engine/`, and the former `v2` integration branch, retired on 2026-10-30 (#1). In #5, "re-cut per family on v2" means per family as it moves onto the decode-first engine; that work now lands on `main`. In #8, "v2 ships to main through per-family minor releases" means the engine's families ship per release; only the "v2 remains the integration branch" clause names the branch, and it is superseded. The decisions themselves are unchanged.

| 10 | Progress value: `composeProgress` gains an optional `range?: { value, min, max }`. It matches CDEF 5 exactly: 16-bit signed, unclamped, with the split from `engine/progress.md` DET3 and the trace recording overflow past the track. The existing normalized `value` stays as a compatibility facade with a declared 0..10000 mapping. `min`/`max` never change what `value` means. Passing both `value` and `range` throws a `TypeError` rather than letting one silently win (PM clarification on 2026-10-22, from the #440 Tier-2 review). | Approved by maintainer (2026-10-22) |
| 11 | Progress indeterminate: add optional `indeterminate?: boolean` and `phase?: number` (integer 0..255, the stored phase byte at draw time). The composer draws one frame and reports the phase after the draw, because frame mode resets it. The 3-tick idle advance (IDLE rows) lives in a helper in the interactive layer, not in the composer. | Approved by maintainer (2026-10-22) |
| 12 | Accessibility divergence: title-bar widgets (close, zoom, collapse) on inactive windows stay real, focusable, operable buttons. The original makes them inert (`engine/window-widgets.md` HT2: no hit test on an inactive window). The engine still implements HT2 as decoded and traces it, and only the public layer (`renderWindow`, declarative) keeps the buttons. Widget art still follows the decode, which is unaffected: at rest, close and collapse art is part of the window's own (active or inactive) template pixels; the only widget draw gated on the active state is the partial-zoom widget (WD5) (`engine/window-widgets.md` WD rows). Wording corrected 2026-10-22 (#437). Why: on the web a background window is part of the page, and inert controls would drop out of the tab order and away from assistive technology. Recorded in `docs/spec/kdef-faithfulness-ledger.md` ("accessibility→decode") and at the code site. **Narrowed 2026-11-01 (#614):** the pointer half no longer diverges. A pointer press (mouse, touch or pen) on a widget of an inactive window only activates and raises the window and can start a frame drag; no widget action runs (`engine/inactive-window-input.md` IP1, decode HT2 and Apple's `wInDrag` contract). A first pointer press on an inactive window's grow box likewise only activates it, as a content press; resizing starts on the next press (IP14). Keyboard and assistive-technology activation is unchanged: the buttons stay focusable and operable on inactive windows. | Approved by maintainer (2026-10-22); pointer half narrowed by maintainer (2026-11-01, #614) |
| 13 | Runtime font substitution for window titles. The runtime cannot draw the original's title fonts: there is no Font Manager condensed face, and the substitute bitmap font is taller. So (1) titles are drawn and measured at full width, the declared default for `engine/window-widgets.md` TT2's condensed width is SWc = SW (not SW − titleLen), the title plate fits the text as drawn, and plain-face truncation applies only when SW does not fit the room, where the room is capped at the plate but never below the title rect's own width (room = min(TX5 room, max(plate right − title x, title rect width))), so truncated titles don't run onto the bezel, and templates whose plate is narrower than the title rect (floppies, 1138) don't truncate titles that fit (amended 2026-10-23, after the #453 title rows and the 0.4.0 round-2 release review); (2) the decoded clip and baseline (TX) are kept, except that when the substitute font's ascent would start above the title rect, the baseline moves down by exactly that overflow (baseline = max(decoded, rect.top + ascent)), so glyphs fit the title rect. A wider clip was tried first and overdrew frame art on windows-31 and floppies (amended 2026-10-23). Reason: following the font-dependent geometry with a different font made text overflow bezels (evolution) and clipped glyph tops (1990), as the 0.4.0 release review showed. | Approved by maintainer (2026-10-23) |
| 14 | CI runs in two tiers (#598). **PR tier** (`ci.yml`, every PR to `main`, required check `Gates + build + browser contracts`): gates, engine diff and builds, the bounded sharded Chromium rendering contracts, the exact Linux goldens, the installed package consumer contract; Chromium only. **Release tier** (`release-gate.yml`, aggregate `Release gate`): the full extended matrix (called from `rendering-extended.yml`, not copied), the required Firefox/WebKit interaction contracts (`interaction-specs.mjs`, source and built, with their per-spec, per-engine coverage check), the pinned-container golden verify, `lint:themes --strict --decoded`, the package consumer contract, `verify:scenes` (required since #599; fixtures recorded in the pinned image) and the `loc:src` trend against the previous release tag. It runs on manual dispatch, weekly on `main` and on same-repository PRs from `release/*`. A `v*` tag push does not re-run it; it only checks that the tagged commit has a successful release-gate run, so a release costs two full runs (release PR, then the post-merge commit). A release is tagged only on a commit with its own green release-gate run, linked from the release PR and the GitHub release notes (CONTRIBUTING "Cutting a release"). A red weekly run blocks the next release only: it opens or updates one `release-gate` issue (closed by the next green run on `main`), and the tag check fails because the tagged commit has no green run; PR merges continue. `Release gate` must never be a required branch-protection check, because its jobs skip on ordinary PRs and GitHub counts a skipped required check as passing. **Moved out of the PR tier (maintainer decision, 2026-10-31):** the Firefox/WebKit interaction contracts (`Interaction contracts (firefox)`/`(webkit)`), now required jobs of the release gate. Chromium still runs those specs on every PR in the bounded shards, and the extended matrix also runs them in both engines; the Chromium rendering shards and the exact Linux goldens stay required on every PR. Any later move is recorded here, because CONTRIBUTING forbids removing coverage silently. | Adopted; the maintainer confirmed the red-weekly policy and the interaction move (2026-10-31) |
