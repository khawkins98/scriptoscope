# Control resource preparation contract

Scope: compatibility-preserving shared preparation for the existing engine theme prepareBodyPattern, bevel loadBodyPattern, header bindPattern and tab bindPattern operations. Current source anchor is commit 05a8acc5c31dbc468f7267df0057addaa31149a4, tree 52f77ec13978baceaa39fa4d0d28516210cfd54a; the doc-only commits through 96ac9a1d57c4e5c38aa852c1068b233e8a78decc do not change those source bytes. Exact reference hashes are at the end. This contract changes no public policy or request domain and does not supersede full bevel BV01–BV08. Every behavior below is **C: current compatibility/source behavior**, not independent original/native evidence. **U:** original Resource Manager ownership, device palettes, original font/transfer state and unsupported native outcomes remain unresolved here. No new native claim follows from sharing preparation.

## RP01 — ownership, public entry gates and snapshots

Each binding searches only the selected face owner’s pattern catalog; no helper walks a base chain or substitutes another owner. Face selection remains with its existing family. Resource ID comparisons are strict equality; no absolute alias, number coercion, sign normalization, ID validation, sorting or occurrence-order inference is added by common catalog code.

Engine prepareBodyPattern runs only for declared bodyEnvironment ppat requests in themeResourceChain, before provider traversal and dependent pattern decode. It receives the owner, carried links and raw requested ID. Generic engine ppat enumeration outside bodyEnvironment is unchanged. Body request preparation does not itself publish engine resource requests. The synchronous engine painter still owns request order and status observations.

Bevel loadBodyPattern runs after face decode, admission, browser text/color/sizing preparation, only on the non5 branch. Missing bodyRequest returns no buffer/no solid eligibility. Invalid non5 mode or missing slice keeps its existing fallback event and no solid eligibility; mode5 uses its separate body path. Catalog code does not move any of these gates, compute sourceBg early, or strengthen legacy admission. It retains ordinary live owner/element/nested references and delayed reads except the snapshots already required by BV07.

Header bindPattern is called synchronously during prepareHeader after the selected face element’s consumed properties have been structured-cloned, owner base URL/profile captured, face URL/identity constructed and face-selection diagnostic recorded, but before ordinary face decode and metadata admission. It reads ID from element.bodyRequest?.resourceId before catalog enumeration, even if undefined. It uses the actual selected owner’s then-current catalog and optional census. Its selected pattern asset/provenance are captured before later face decode. Header body dependency decode is demanded only after face decode, metadata/geometry admission and bodyVisible; binding itself is not delayed to that gate. Unknown clip and special-origin gates return before prepareHeader as currently implemented. An empty rectangular clip does not move these stages: prepareHeader/catalog binding, ordinary face decode and metadata admission still occur; only later body dependency and sampled visibility demand are skipped when empty.

Tab bindPattern runs after the caller has copied the selected owner, structured-cloned the whole pattern catalog and optional ppat census, structured-cloned the face element and any retained header, awaited face decode, admitted source/metadata/geometry, rasterized label, and performed demanded sampled-band preparation. It is called only when tabCenter is nonempty and patternId !== 0. Therefore public tab ID 0 does not bind or decode a ppat; the other three binding paths can request ID 0. The pure binding algorithm does not gain its own ID-zero rejection or signed16 check. Existing earlier geometry admission remains in its caller. Public tab later mutations of the original catalog do not retag its copied owner. Do not relocate tab’s earlier structuredClone to the selected row: unrelated noncloneable pattern metadata can already reject during the earlier snapshot.

## RP02 — catalog acquisition and link observation order

Engine/header/tab obtain Object.entries(owner.manifest.patterns ?? {}) before reading carried link fields. Entries eagerly materialize every own enumerable string-keyed value in standard JavaScript order; unrelated property getters can throw before link reads. Then both bodyPattern and bgPattern are read into an array. Both array.map searches run before find(Boolean), even when the first link succeeds: the second search is not short-circuited. Repeated links are not deduplicated. Matching is by exact catalog key and exact sourcePpatId, with the engine’s additional per-candidate usable filter below. A linked hit suppresses the subsequent full candidates filter, but does not undo earlier eager value access or the second mapped search.

Header/tab link comparison does not prefilter link type/truthiness. Empty string keys can match; a nonstring link does not strictly equal an Object.entries string key. Engine maps a link only when typeof key is string, including empty strings. Do not replace map/find with a short-circuit loop or universal truthy-key policy.

Bevel first obtains the catalog reference without enumerating values, then builds both carried link values and their reason labels. It visits truthy links in order with Set deduplication. Direct patterns[candidate] lookup may see inherited properties or perform current property-key coercion; no string-only admission is added. Successful exact-ID link stops this loop and can avoid Object.keys entirely, including proxy enumeration traps. Rejected links emit linked-pattern-id-mismatch, with current linked resource details when truthy, before the next link or fallback enumeration.

Only after no accepted bevel link does it call Object.keys(patterns), then read patterns[candidate].sourcePpatId lazily per key. It returns ambiguity immediately on the second match, so later getters are not observed. After selection it rereads patterns[key] when key is truthy; do not carry an earlier entry object instead of this second lookup. A sole empty-string matching key leaves key falsy at this final access and follows the existing miss path; two matches still produce ambiguity. Preserve these malformed-value/key behaviors without claiming original support for them.

No common helper may turn lazy keys into eager entries, return a stable row where a caller currently rereads it, invoke additional getters for a broad descriptor, enumerate prototype properties, or normalize raw catalogs into a Map. Preserve Object.keys/Object.entries/proxy/accessor exception and read timing, not only the final chosen row.

## RP03 — filter position, ambiguity and census

Engine usable is sourcePpatId === requested ID AND typeof asset is string AND asset.trim() truthy. It is evaluated during linked-entry searches and during the unlinked candidates filter. Invalid-asset matching entries do not count as usable candidates. Exactly one usable candidate wins even if another same-ID entry has an unusable asset; a link to an unusable row can fall through to another usable row. No candidates returns unknown if any catalog row still has the requested ID or the optional raw census contains it; otherwise null. More than one usable candidate is unknown immediately. Preserve the reason ambiguous or undecoded same-face-owner ppat, not a NULL retry. Census is short-circuited when the candidate count or matching catalog row already establishes unknown.

Header/tab first select/count exact-ID entries with no asset usability filter. A linked same-ID row wins even if its asset is unusable; it then rejects rather than trying an unlinked usable row. With no accepted link, two ID matches are ambiguous even if only one asset is usable. Only after a unique selected row do they test typeof asset is string and asset.trim() truthy. Do not filter unusable rows before ambiguity or link choice.

Header ambiguity, unique unusable asset and no catalog row with census presence all return kind ambiguous. No row and no matching optional census returns kind missing. Unique usable returns kind selected with captured asset/key/ID/provenance. An absent census is treated like no matching census, not unknown. Because header obtains ID with optional access before normal metadata admission, undefined can strictly match an absent sourcePpatId; do not repair it in this binding layer.

Tab multiple matches return status unsupported/reason ambiguous-same-owner-ppat. No row with matching optional census or a unique row with invalid asset returns unsupported/undecoded-same-owner-ppat. No row/no matching census returns missing. Unique usable returns ready URL/resource. Keep the distinction between ambiguous and undecoded reasons. No header-style generic ambiguous reason is substituted.

Bevel does not consult ppat census at all and does not filter asset usability. A unique exact-ID catalog row can proceed to current asset URL construction/decode even with a malformed/blank asset; failures remain failures. Unlinked duplicate IDs yield missing event ambiguous-legacy-pattern-order with no solid eligibility. No usable final row yields same-face-owner-pattern-unavailable and raw-solid eligibility only if requested ID is integer signed16 and both slice values are integer bytes. Malformed/unsupported mode and ambiguity do not become solid eligibility. A catalog getter returning no object can still throw during the lazy ID read; do not add optional access to suppress it.

## RP04 — selected transport and provenance order

There is no universal immutable resource row. Preserve selected scalar fields and evaluation order at the boundary each caller currently owns. Do not deduplicate repeated asset/provenance getters or add trimming/coercion beyond the existing caller.

Engine: after choosing the usable row, call assetUrl(owner, pattern.asset) first. Then form selection.resource with requested signed ID, null sourceCinfId, selected key, captured URL and a shallow copy of provenance when truthy. The shallow copy is conditional and can invoke nested property getters; nested objects remain aliased. If URL construction throws, provenance copying has not happened. A successful plan holds URL and selection before dependent decode.

Bevel: after final truthy-key reread, capture URL first, then build selected trace/provenance only when a trace collector exists. Provenance is shallow-copied in that selected trace; no trace means no such provenance read/copy for this successful-selection step. selected signedId is current pattern.sourcePpatId ?? null, not unconditionally requested ID. Selected link-rejection resource records retain their existing raw provenance references. Preserve their existing callback/freezing alias consequences. Returned selected trace is the same object later enriched with bodyPaint; do not manufacture a second selected row.

Header: after ID-only count and usable-asset gate, capture asset/key/ID and structuredClone selected provenance into the binding result. This clone happens before the body URL exists, and may reject before face decode/body visibility admission. Later loadPattern uses the captured owner and asset, runs checkedUrl (nonempty trimmed string, then assetUrl), builds its selection using the already captured provenance, and awaits decode. It does not rerun catalog selection. A clone failure can therefore win over a later body URL failure; do not reorder them. Header face URL construction already occurred before this binding; the ordering here concerns the pattern body URL.

Tab: selected pattern body URL is computed first, then selected resource is constructed and truthy provenance structured-cloned. This is separate from the earlier public whole-catalog snapshot, which already cloned provenance before face decode. Do not remove either capture merely because a normal plain value appears equal. The binding algorithm’s URL-before-selected-provenance order remains; public reachable getter behavior is bounded by the earlier snapshot. Core data that was already cloned must not be reattached to live original rows.

assetUrl passes through blob/http/https/data refs and prefixes other values with current owner base URL as it already does; do not introduce a new global checkedURL operation. Header’s later checkedUrl has its own stricter validation. URL getters/baseUrl getters can throw or differ on repeat; preserve per-caller URL computation count and capture point.

## RP05 — dependency decode, statuses and diagnostic completion

Catalog preparation is synchronous except bevel loadBodyPattern’s selected decode; no shared Promise is started for unselected rows. Selected dependency decode uses the existing loadCicnBuffer URL promise cache. Real decode rejection propagates unchanged; it is never converted to missing, ambiguity, solid background, fallback or another row. No extra per-binding cache, Promise.all reordering, all-owner loading or repeated selection is introduced.

Engine: prepareBodyPattern result is prepared once into bodyPatterns before provider traversal. Provider demand uses bound captured URL/selection, tags the selected owner, checks current chain lifetime before decode, and returns decoded pixels or unknown/null plan status. Existing engine requests/trace publication remain at synchronous ResourceChain/painter calls. Generic checkable catch behavior stays outside this binding helper and is not introduced for the four public pattern-binding operations.

Bevel: trace selected row is recorded only after successful selected pattern decode. Rejection/missing/link observations occur synchronously where already described. Pattern body completion enriches the recorded selection only after border/labels/final clip succeed. A later renderer failure leaves selection without completed pattern body. withControlDiagnostics trace construction/freezing stays outside the render catch: existing nested alias/getter/freezing failures can prevent all onComplete calls and supersede caught render error. No new catch, clone or safe-freeze behavior is added by preparation.

Header: loadPattern is called only when bodyVisible. It records missing with same-face-owner-pattern-unavailable or ambiguous-body-selection as appropriate; ambiguous returns unsupported as before. Ready selection reason same-owner-pattern-admission is recorded after successful decode with usage admission. Only the completed admitted surface later adds completed-header-pattern-inset-union/usage paint. Decode failure does not publish selected pattern admission. A visible empty body, unverified geometry, source rejection or other later failure retains current headerSurface diagnostics/outcome; shared preparation does not publish successful paint early.

Tab: bindPattern is skipped for empty center or ID 0. Unsupported binding returns unavailable unsupported-pattern with its reason. For ready or missing binding, caller records its body selection/miss BEFORE selected decode, using reason same-selected-face-owner-pattern or missing-pattern-solid-erase and usage paint. A subsequent decode rejection therefore retains that selection observation in the error trace; do not adopt bevel/header postdecode record timing. Selected body resource identity comes from the earlier copied owner/key. Body/label admission and final tab trace remain unchanged.

## RP06 — sampled companion mechanics and limits of sharing

Only common decode transport and literal size/mask comparisons may be shared; descriptor admission, demand, lifetime, mismatch outcome, source rejection ordering and completion remain caller policy. Do not require a universal proof, regex, data length guard, opaque colors or cancellation behavior. Pattern binding and sampled-color preparation are separate resources.

Engine theme adapter: finite metadata requires model/comparison, string display policy matching owner and positive integer dimensions. sampledDeclaration additionally requires proof different/opaque-display-mismatch, matching descriptor dimensions, nonempty trimmed string asset and derivedPath matching cicn-sampled/<single-name>.png. It snapshots proof/descriptor and sampled URL before ordinary decode. Lazy prepareSampled memoizes its promise, skips equivalent/ineligible, checks lifetime before and after decode, rejects decode/lifetime errors, and accepts only same width/height/data length and identical alpha bytes. Mismatch returns without sampled acceptance; it does not throw or select another descriptor. Generic versus public lazy demand remains existing theme/prepareSamples policy. No new use of this stricter admission for bevel, header or tab.

Bevel: matching model/comparison/policy/dimensions is enough for descriptor identity; string asset and matching sampled path are required, but not proof different, not trimmed/nonempty asset, not positive-integer dimensions beyond equality to decoded source. At first visible opaque expanded band only, decode once; equivalent/copy/invisible bands demand none. Descriptor remains a live object across await. Successful width/height and alpha equality accepts; unlike engine/tab it has no explicit decoded data.length equality guard. Mismatch retains compatibility raster; decode rejection rejects the render. No release/AbortError checks are added. BV06/BV07 remain complete authority for the surrounding behavior.

Header: facade demands sampled decode after body decode, background/source checks and geometry needsSampling; eligible descriptor has matching model/comparison/profile/dimensions, string asset with length>0 and matching sampled path. checkedUrl can still reject whitespace. No descriptor/proof-different requirement is added. Facade captures URL from its already cloned descriptor, decodes, then the existing header driver validates width/height/data length and alpha after its own source checks. Invalid/missing sampled support yields current unverified-line-sampling unsupported result when needed. Do not relocate driver validation into an eager common preparation gate or substitute bevel mismatch fallback. Driver is a retained validation owner.

Tab: when tabNeedsSampledBands and not equivalent, descriptor requires matching model/comparison/profile/dimensions, asset and derivedPath both strings with nonempty trim; derivedPath need not match the sampled directory regex. It decodes then uses validTabCompanion: same width/height/data length and identical alpha. Mismatch returns null, becoming current unsupported-sampling unavailable outcome; decode rejection propagates. No extra source-alpha/clip demand test is added: its geometry demand differs from bevel’s actual visible opaque sample demand. validTabCompanion remains live for driver admission and is not deleted with a facade adapter.

Pixel compare only compares mask alpha as presently specified; it does not compare RGB, force opaque sampled colors, mutate the source/mask or construct native proof. Preserve loop short-circuit and failure timing for malformed supplied pixmaps. The new helper may expose separate size/mask policies; an unconditional length check or fixed order shared by all four is not authorized. Existing loadCicnBuffer cache eviction on release permits a pending caller decode to finish; engine’s separate caller lifetime may instead reject. Do not add that lifetime to header/tab/bevel.

## RP07 — authored immutable fixture descriptions

These are source-derived synthetic behavior descriptions, not runnable tests, oracle data or native captures. Binding-operation cases distinguish internal policy from public timing; public tab snapshots often materialize getters before the binding operation itself.

- F01: own entries a with requested ID 7 and blank asset, b with ID 7 and valid asset; no links/census. Engine selects b (one usable). Header is ambiguous; tab unsupported ambiguous-same-owner-ppat; bevel missing ambiguous-legacy-pattern-order with no solid eligibility. No helper may choose b universally.
- F02: carried link a has ID 7 and blank asset; b has ID 7 and valid asset. Engine rejects a as unusable and selects b via fallback candidates. Header selects a before usability then returns ambiguous; tab returns undecoded-same-owner-ppat; bevel selects a and proceeds to its existing URL/decode behavior without trim validation.
- F03: no decoded catalog row, optional census includes ID 7. Engine returns unknown; header ambiguous; tab unsupported undecoded; bevel records same-face-owner-pattern-unavailable and can enable raw solid with valid signed16/slice. With census absent, engine null/header missing/tab missing; bevel result is unchanged. An accessor on census must not run for two candidates or an engine unusable matching catalog row that already establishes unknown.
- F04: catalog valid row at ID 0. Engine, header and valid bevel request 0 can select it. Public tab center at ID 0 performs no bind/decode/selection trace, retaining solid background path. Calling a pure ID matcher with 0 does not authorize changing the public tab gate.
- F05: valid first link, unrelated catalog value getter throws. Engine/header binding eagerly reads values and throws before reading links. Bevel direct first link can select without invoking unrelated getter or enumeration. For public tab the earlier full-catalog structuredClone may already throw before ordinary face decode; do not claim its getter necessarily waits until bindPattern.
- F06: first and second link name the same valid row with counting sourcePpatId getter. Engine/header/tab mapped link searches can read twice before find(Boolean); bevel Set deduplicates and stops after first exact match. With second link getter throwing, both links are read before even bevel’s first direct match; do not lazily read link fields one at a time.
- F07: inherited catalog property named carried has exact ID 7; no own matching row. Bevel direct linked access can select it. Entry-based engine/header/tab ignore it; their ordinary miss/census policies apply. An empty-string own matching key can be selected by entry-based string links; bevel skips the empty link and its sole-empty-key fallback follows missing. Do not normalize keys to make these equal.
- F08: selected row’s URL work and provenance clone both throw distinct failures in a binding-operation description. Engine URL failure wins before shallow provenance; bevel URL failure wins and diagnostics-disabled success never copies selected provenance. Tab body URL failure wins before its selected deep clone, separately from its earlier whole-catalog clone. Header selected deep-clone failure occurs before its later body URL computation. A successful URL is captured once even if owner base URL later changes at the current await boundary.
- F09: hold a selected decode and reject it. Bevel/header have no selected pattern record because they publish selection after successful decode. Tab has already recorded selected same-selected-face-owner-pattern; engine remains in its existing provider-build failure/lifetime behavior. None retries another row or erases solid due to this rejection.
- F10: hold header face decode, change original catalog asset after binding. Header uses captured selected asset and cloned provenance for later body decode. Hold bevel face decode and change its ordinary live catalog before loadBodyPattern: bevel can see the later row; after selected pattern URL is captured, a subsequent mutation does not change the in-flight URL. Tab uses its earlier cloned catalog; new original rows are invisible to that invocation.
- F11: same dimensions/mask but different sampled RGB accepts wherever the caller has admitted descriptor and demanded sample; RGB equality is not required. Wrong mask: engine/bevel retain compatibility raster, tab becomes unsupported-sampling, header becomes unverified-line-sampling unsupported. Decode rejection propagates in all; engine lifetime rejection remains separate. A tab nonempty derivedPath outside the sampled directory can be admitted while engine/header/bevel path admission rejects it.
- F12: demanded sample wholly transparent/clipped source band. Bevel may avoid decode after actual visible-alpha scan; tab geometry-only sampled demand may still decode; header uses its own source-aware geometry; engine public lazy preparation uses bandVisible. Do not deduplicate these distinct demand policies into one visibility rule.

## RP08 — exact boundary and deletion requirements

Implement only common resource preparation and thin adaptations of the named functions. Exact proposed editable files for this extension: src/engine/resources/controlBody.ts, src/engine/resources/theme.ts, src/bevelButtonFacade.ts, src/headerFacade.ts and src/tabFacade.ts. The first three are inside the already approved full bevel boundary; the latter two are the requested boundary extension. This contract does not authorize moving shared resource selection into a second location. src/controls.ts and src/engine/families/bevel.ts remain subject only to the prior full bevel authorization; this extension adds no edits there. The published baseline names loadBodyPattern in controls as a source behavior reference, while its approved single replacement owner is the bevel facade; do not read an unapproved candidate to infer new semantics. No new file outside that previously approved boundary is required. Before runtime dispatch the exact current common-core bytes must be preflighted; this baseline contract does not pretend a future module already exists.

Delete header/tab local bindPattern algorithms and replaced local PatternBinding type definitions/import debris once both use the shared preparation core; do not retain wrappers that duplicate lookup/count/census/asset validation. Shared types can move once to the common resource module with all added imports accounted. Core must retain one common eager-entry selection/count/census mechanism where it genuinely serves engine/header/tab, with explicit during-match versus after-selection asset policy. Bevel keeps its lazy-key and repeated-row-read strategy inside the shared resource execution boundary, not a second facade catalog implementation. Distinct output/status/capture policies are not deleted as though they were dead code.

Retain header prepareHeader snapshotElement/checkedUrl/backgroundColor/samplingMatches/loadPattern and surface/column orchestration except necessary thin binding call/type edits. Retain tab selection, owner/element snapshot, metadata/origin/geometry/color/label/orchestration and validTabCompanion driver use. Retain current source/background/clip/sampled admission ordering and diagnostics. No whole header/tab rewrite, selector cleanup, label/font/geometry change, new public options, stronger universal admission, fallback renderer, tests/oracles/captures, version/release/tag or checker edit is included. The full bevel contract remains unchanged.
