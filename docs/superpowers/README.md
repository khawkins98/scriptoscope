# Historical design proposals

The `plans/` and `specs/` directories preserve dated design proposals and their
original terminology. They are useful for understanding alternatives considered;
they are not instructions for integrating the released package or proof that
proposed behavior shipped.

Start with the [documentation task index](../index.md) for current guides and
references. For architecture changes, consult the [integration decisions](../v2/DECISIONS.md)
and role-gated [spec index](../spec/README.md). Runtime implementers instead use
their [brief](../spec/engine/IMPLEMENTER-BRIEF.md) and its explicit allowed paths.

Keep these records intact. Explain a superseding decision in its authoritative
home and add a route when needed, rather than editing a proposal into a partial
account of the current implementation.
