A few tags. A whole new look.

Start with a working page, choose the attributes you need, then bring your own scheme. Your content and event handlers stay yours.

01 / START WITH A PAGE

Copy. Save. Try it.

Copy this into an HTML page and serve it through your usual web server or local dev server. The stylesheet, runtime, and bundled themes come from this project’s GitHub Pages; there’s no build step or npm install required.

The starter uses 1138. Choose a scheme in the showcase and follow its Install link to carry that choice here.

complete starter
<link rel="stylesheet" href="https://khawkins98.github.io/scriptoscope/scriptoscope.css">
<article data-scriptoscope-window data-scriptoscope-title="Hello">
  <h2>Your content, wearing a scheme.</h2>
  <label for="name">Your name</label>
  <input id="name" data-scriptoscope-field value="Hello world">
  <button type="button" data-scriptoscope-button
          data-scriptoscope-default>Save</button>
</article>
<script type="module">
  import { mountDeclarative } from 'https://khawkins98.github.io/scriptoscope/scriptoscope.js';
  const handle = await mountDeclarative({
    themeBaseUrl: 'https://khawkins98.github.io/scriptoscope/themes',
    pageThemeDefault: '1138',
  });
</script>

Use an HTTP URL for local development: a file:// tab cannot reliably load modules or WebAssembly. Keep your layout CSS; native borders extend beyond the content dimensions.

02 / MARK UP YOUR HTML

Tell each element what it is.

Add data-scriptoscope-* attributes to ordinary HTML. In a component framework, pass them through to the rendered elements. You don’t need to replace your content with a separate component system.

window and controls
<article data-scriptoscope-window
         data-scriptoscope-title="Notes"
         data-scriptoscope-window-type="titled-utility-window"
         data-scriptoscope-widgets="zoom,collapse">
  <p>Real HTML lives here.</p>
  <label><input type="checkbox" checked> Keep it playful</label>
  <input type="range" min="0" max="100" value="50"
         aria-label="Volume">
  <button type="button" data-scriptoscope-button>Save</button>
</article>
The attributes you’ll reach for first
AttributeHow to use it
data-scriptoscope-windowPut this on an element to turn its children into a window body.
data-scriptoscope-title="Notes"Set the title-bar label.
data-scriptoscope-window-type="titled-utility-window"Choose a frame. The default is document-window; try titled-utility-window for a palette or dialog for a dialog.
data-scriptoscope-widgets="zoom,collapse"Wire only these title-bar actions. Other widgets may remain in the original artwork; their actions are disabled.
data-scriptoscope-width="320" / data-scriptoscope-height="200"Set content dimensions in pixels. Without them, the initial size comes from your HTML. Leave room around the element for the scheme’s native borders.
data-scriptoscope-x="24" / data-scriptoscope-y="40"Opt into absolute positioning relative to the nearest positioned ancestor. Omit both to keep the window in your normal Grid, Flex, or document layout.
data-scriptoscope-theme="monkey-paradise"Override the page scheme on a window or an ancestor. A theme bundle URL also works.
data-scriptoscope-button / data-scriptoscope-defaultTheme a real button; add default for the default-button ring. Your click handler still belongs on the button.
data-scriptoscope-fieldOpt a text input or textarea into the themed field treatment. Keep ordinary labels, names, and values.
data-scriptoscope-control="off"Checkboxes, radios, range inputs, and selects are themed automatically inside the mounted root. Use off to keep one native.
data-scriptoscope-theme-switcherPut this on a select whose option values are theme slugs. A selection rethemes the mounted page.
data-scriptoscope-window-id="notes"Give a window a stable identity when using layout persistence.

For tabs, icons, cascades, initial states, and the complete vocabulary, see the attribute reference.

03 / CONFIGURE THE RUNTIME

A small set of options.

Pass these JavaScript options to mountDeclarative(). Replace the starter’s article with the desktop markup below, then replace its mount call with these options. This adds a theme selector, shares its selection in the URL, and remembers window layout.

desktop markup
<main id="desktop">
  <select id="scheme" data-scriptoscope-theme-switcher
          data-scriptoscope-control="off" aria-label="Choose a scheme">
  </select>
  <article data-scriptoscope-window data-scriptoscope-window-id="notes"
           data-scriptoscope-title="Notes">
    My notes stay real HTML.
  </article>
</main>
mount options
// Replace the mount call in the starter with this setup.
const themes = await fetch('https://khawkins98.github.io/scriptoscope/themes-manifest.json')
  .then(response => {
    if (!response.ok) throw new Error('Could not load the theme catalog');
    return response.json();
  });
const requested = new URL(location.href).searchParams.get('theme');
const selected = themes.some(theme => theme.slug === requested) ? requested : '1138';
const switcher = document.getElementById('scheme');
for (const theme of themes) {
  const option = new Option(theme.name ?? theme.slug, theme.slug);
  option.selected = theme.slug === selected;
  switcher.add(option);
}
const handle = await mountDeclarative({
  root: document.getElementById('desktop'),
  themeBaseUrl: 'https://khawkins98.github.io/scriptoscope/themes',
  pageThemeDefault: selected,
  themes,
  syncToUrlParam: 'theme',
  persistKey: 'my-desktop',
});
Common mount options
OptionPurpose
rootThe element to scan; defaults to document. Scope it to your app or desktop to leave surrounding navigation untouched.
themeBaseUrlWhere the bundled theme directories live. Each slug resolves underneath this URL.
pageThemeDefaultThe starting scheme slug or theme bundle URL, used where no element overrides it.
themesThe catalog array. It supplies folder-picker entries and the registered slugs used for URL deep links.
syncToUrlParamUse a query parameter such as theme to read and share the selected registered scheme.
persistKeyOpt into saving window layout in localStorage. Pair it with stable window IDs; omit it to start fresh on reload.

The returned handle lets you call await handle.retheme('monkey-paradise') to switch schemes. Call handle.disconnect() when removing the integration; it restores the ordinary HTML. Read the full runtime reference →

04 / BRING YOUR OWN KALEIDOSCOPE SCHEME

Give an old favorite a new home.

Use an original Kaleidoscope scheme archive or resource fork. The browser loader accepts .sit, .rsrc, .hqx, .bin, .as, .adf, and .cpt files. Decoding happens in the browser; the file picker in the example doesn’t upload the file to a server.

Try a file in the showcase →

Let visitors pick or drop a file.

This is another complete page. It mounts a window, decodes a selected file, registers it with the runtime, and applies it to the page.

complete custom-theme starter
<link rel="stylesheet" href="https://khawkins98.github.io/scriptoscope/scriptoscope.css">
<article data-scriptoscope-window data-scriptoscope-title="Your page">
  <p>Pick a scheme to change this window.</p>
</article>
<button id="pick-theme" type="button">Pick or drop a Kaleidoscope theme</button>
<p id="theme-status" role="status"></p>
<script type="module">
  import {
    mountDeclarative, attachThemeDropZone, loadKaleidoscopeScheme,
  } from 'https://khawkins98.github.io/scriptoscope/scriptoscope.js';
  const handle = await mountDeclarative({
    themeBaseUrl: 'https://khawkins98.github.io/scriptoscope/themes',
    pageThemeDefault: '1138',
  });
  attachThemeDropZone(document.getElementById('pick-theme'), {
    onFile: async file => {
      const status = document.getElementById('theme-status');
      status.textContent = `Decoding ${file.name}…`;
      try {
        const theme = await loadKaleidoscopeScheme(file, { source: file.name });
        handle.registerTheme('my-scheme', theme);
        await handle.retheme('my-scheme');
        status.textContent = `Loaded ${file.name}`;
      } catch (error) {
        status.textContent = `Could not load this scheme: ${error.message}`;
      }
    },
  });
</script>

Or serve a scheme from your own site.

Keep the starter’s handle and add this in the same module. Host the archive at the example path, or change the URL to match your files. Cross-origin hosts must allow your page to fetch the file.

hosted scheme
// In the starter's module, import this alongside mountDeclarative:
import { loadKaleidoscopeScheme } from 'https://khawkins98.github.io/scriptoscope/scriptoscope.js';

// After creating handle, load an archive from your own site:
const theme = await loadKaleidoscopeScheme(
  new URL('./themes/My Scheme.sit', location.href).href,
);
handle.registerTheme('my-scheme', theme);
await handle.retheme('my-scheme');

A local picked file is a temporary preview. To use it after reload, serve it from your site and load it again. Retain the scheme author’s credits and original terms when sharing a theme.

Find preserved schemes at Mac Themes Garden and the Kaleidoscope Scheme Archive. For a deployed site, you can also self-host the runtime and its decoder assets.
