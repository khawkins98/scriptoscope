# Explicit host migration

`mountDeclarative`, `mountOwnedDeclarative` and their mount-specific types are removed. The library no longer scans the DOM, automatically promotes newly discovered elements, retries failed discovery, or maintains a root-wide move observer. Hosts explicitly choose sources, attach them, replace themes and release their lifetimes. Per-control property and carrier-location observers remain: they synchronize an explicitly promoted native control and restore only owned mutations; they do not discover or promote new sources.

## Public primitives

The package root and `scriptoscope/declarative` export `promoteGuardedButton`, `promoteGuardedControl`, `restoreButton` and `restoreControl`. Both guarded promoters take `(source, theme: ThemeInput, signal: AbortSignal, canCommit: () => boolean)` and return `Promise<HTMLElement | null>`. Controls support native checkbox, radio, range and select elements. Existing `promoteButton` and `promoteControl` defaults are unchanged. The declarative entry retains window, field, icon, tabs, picker, modal, drop-zone and parsing primitives. The opt-in `scriptoscope/renderer` entry remains separate; all entries share one implementation graph.

A synchronous, side-effect-free predicate should require an active host, current source attempt, current theme generation and containment in the host root. A false predicate releases pending preparation without insertion. A thrown predicate rejects with the original thrown value after releasing preparation. Signal/location checks still apply. `disposePromotedButtonFace(source, previousFace)` releases one replaced button face without restoring the hidden source or removing the new face. After a successful guarded button refresh, transfer focus as needed and release the previous face with this function; a rejected refresh keeps the previous face. Controls replace and dispose their previous face internally. Predicate revocation alone does not universally disable an already committed face: on removal, replacement or disposal, abort its lifetime and call its restore function. Preserve native source nodes and their form association. Restore only after aborting; release dependent faces before disposing themes.

`ScriptoscopeWindow.promote(source, {manager, theme, signal})` prepares an explicit window. Await it before recording success. Use `restoreOriginalElement()` for teardown that restores the original live children without a user close, and `unmount()` for close semantics. Abort pending preparation when ownership changes, including an ancestor leaving the root. A source changing parents during preparation cancels it; a root change must be guarded by the host lifetime. Existing geometry, content-fit observation, native identity, accessibility and window events remain.

The package root and `scriptoscope/declarative` export `restoreField(source: HTMLInputElement | HTMLTextAreaElement): void` and `restoreTabs(source: HTMLElement): void`. These idempotent teardown functions preserve live native nodes, form values and application listeners. They roll back only promotion-owned attributes, class tokens, display changes and tab positions that remain owned; later application edits are retained. Tab teardown removes promotion listeners and faces, cancels pending tab preparation/selection commits and returns face focus to its native tab. Repeated promotion and retheme retain the original rollback baseline. Call these after aborting the host attempt, before disposing its theme. Shared injected stylesheets remain available for other promoted sources. `ScriptoscopeWindow.restoreOriginalElement(): void` is public and idempotent; it restores native content without emitting a user-close event.

## Live persisted state

The root exports `ManagedWindowState`, whose optional fields are `width`, `height`, `z` and `collapsed`. `WindowManager.applyState(host, state, signal?)` returns `Promise<void>`. Omitted fields retain current values. Width and height are content dimensions; z is the same stacking value returned by `describe()`, with the existing active-window offset applied when displayed. Numeric values must be finite. Applying state never invokes title-widget callbacks and works with missing or inert collapse widgets.

Await `applyState` for its chrome commit. Native content nodes remain attached to the persistent host; z-only updates do not repaint chrome. A render failure rejects and preserves previously committed geometry/state. Removed hosts, aborted calls and superseded preparation are no-ops. Subsequent focus advances above restored z values. A later render-affecting operation may supersede a pending call. This does not change active/inactive focus policy. Position remains `setPosition(host, x, y)`; content-only changes can await `refreshScrollbars(host)` once attached.

## Host obligations

Keep explicit records of source identity, attempt lifetime, theme generation, window instance and native restoration. Replacement must invalidate old pending commits and await the current replacement before signaling completion. A completion barrier includes all selected explicit promotions and any post-attachment scrollbar refresh required by the host. Do not infer success from a returned stale/null face. Choose and document typed boot/error policies, including all-failed boot rejection, partial failures and event delivery. Retain ancestry-based theme selection where the host uses it; URL synchronization, persistence, cycling and boot affordances now belong to the host.

`createThemeResolver` and `createOwnedThemeResolver` retain load/register/font-preload/dispose behavior. Internally loaded themes are owned; registered themes and their base chains are borrowed. Dispose host dependents before the resolver; do not dispose borrowed themes. Raw loading, factory and encode hooks, strict resource handling, native callbacks, theme drop and modal primitives remain available.
